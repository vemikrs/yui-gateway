# YuiGateway アーキテクチャ概要

## コアコンセプト

YuiGatewayは、**Entra ID認証とOpenAI互換APIを備えた安全なAIアクセスプロキシ**です。
[YuiHub](https://github.com/vemikrs/yuihub)の思想記録プラットフォームにおける「モデル実行層」として設計され、**思想と実行の分離、記録と推論の非対称性**を尊重した構成を実現しています。

## アーキテクチャ構成

### 1. 認証レイヤー (Authentication Layer)
- **Entra ID統合**: MSALライブラリでトークン取得
- **マルチログイン**: Interactive/CLI/DeviceCode認証
- **トークンキャッシュ**: メモリ内で自動リフレッシュ
- **セキュリティ**: APIキー不要、トークンベース認証

### 2. APIレイヤー (API Layer)
- **FastAPI**: 非同期ウェブフレームワーク
- **OpenAI互換**: `/v1/chat/completions`エンドポイント
- **Pydanticバリデーション**: リクエスト・レスポンスの型安全性
- **モデル対応**: 新旧モデルのパラメータ違いを自動適応

### 3. プロキシレイヤー (Proxy Layer)
- **httpxクライアント**: 非同期HTTP通信
- **Azure OpenAI統合**: リクエスト転送、レスポンス中継
- **エラーハンドリング**: Azure固有エラーのOpenAI形式変換
- **タイムアウト管理**: 設定可能なタイムアウト

### 4. 設定管理レイヤー (Configuration Layer)
- **Pydantic Settings**: 環境変数ベース設定
- **動的読み込み**: `.env`ファイル、環境変数のフォールバック
- **バリデーション**: 必須フィールド、フォーマット検証
- **ログレベル**: 動的ログレベル設定

## 自動プロビジョニングシステム

### Azureリソース管理
- **サブスクリプション検索**: ユーザーのアクセス可能リソースを自動発見
- **デプロイメント検出**: Azure OpenAIのモデル・バージョン情報取得
- **テナント選択**: 複数テナント所属時の対話式選択
- **RBAC自動設定**: Cognitive Services Userロールの自動付与

### アプリケーション管理
- **App Registration**: Entra IDアプリ登録の自動作成
- **サービスプリンシパル**: クライアントシークレットでの認証設定
- **Microsoft Graph API**: REST APIでのアプリ管理
- **設定自動生成**: `.env`ファイルの自動作成・更新

## データフロー

```
クライアント → YuiGateway → Azure OpenAI
    ↓           ↑ トークン取得     ↑
    OpenAI      Entra ID ←───── Azure AD
    互換          認証
    API
```

1. **クライアントリクエスト**: OpenAI互換形式でYuiGatewayへ
2. **認証トークン取得**: Entra IDからBearerトークンを取得
3. **リクエスト転送**: Azure OpenAI APIへプロキシ
4. **レスポンス中継**: Azureからのレスポンスをクライアントへ

## セキュリティ設計

### 認証セキュリティ
- **APIキーレス**: トークンベース認証でAPIキー露出リスクを排除
- **短時間トークン**: 一定時間で期限切れ、自動リフレッシュ
- **RBAC統合**: Azureの細かい権限制御を活用
- **ローカル実行**: ネットワーク経由でのデータ漏洩リスクを最小化

### データセキュリティ
- **PII非記録**: トークンや認証情報のログ出力禁止
- **メモリキャッシュ**: ファイルシステムへのトークン書き込みなし
- **設定分離**: シークレットとアプリコードの分離
- **入力検証**: Pydanticでの入力バリデーション

## 拡張性設計

### モデルルーティング
- **プラグインアーキテクチャ**: 新しいバックエンドの簡単追加
- **設定ベースルーティング**: モデルごとのエンドポイント設定
- **フォールバック機構**: プライマリバックエンド障害時の自動切り替え
- **負荷分散**: 複数エンドポイントへのロードバランシング

### 監視・観測
- **メトリクス収集**: Prometheus/OpenTelemetry統合
- **トレーシング**: リクエストチェーンの追跡
- **アラート**: 異常検知、コスト監視
- **ダッシュボード**: Grafana等での視覚化

## YuiHub連携

### Signalモード統合
- **Trigger実行**: YuiHubからのTrigger呼び出し対応
- **思想記録**: 推論過程のログ記録、分析対応
- **Knot連携**: 意思決定ポイントの記録と連携
- **非対称性保持**: 記録と推論の適切な分離
